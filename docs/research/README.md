## 1. 두 주제의 좌표 — 경쟁이 아니라 앞뒤다

**BIGB = 설치 전 사전 설계.** 카메라 사양·기하로 검출확률을 내고 배치를 최적화한다.

**B안 = 설치 후 사후 진단.** 이미 깔린 장비의 운영 검지 이력을 교차 대조해
"사람이 있었는데 아무 장비도 보지 못한" 구간을 누적한다.

B안 문서 §6 선행기술 표가 이 선을 이미 그어놨고, 거기서
**Choi & Lee (2015) "CCTV Coverage Index Based on Surveillance Resolution", Sensors**
를 *"카메라 사양 + 3D 기하학으로 이론 계산·시뮬레이션 / 실제 검지 이력을 쓰지 않음"* 으로
분류해 두었다.

> **이게 BIGB의 직계 선행기술이다.** BIGB는 Coverage Index 계보에
> "검출기 실측 곡선 f(ρ)·g(θ)·h(o)"를 얹어 이론 기하를 실측 검출확률로 바꾼 것으로
> 위치를 잡을 수 있다. 제안서 차별성 절에 그대로 쓰면 된다.

## 2. BIGB 제안서에 바로 쓸 수 있는 절

현재 `PROGRESS.md` 는 실험 로그로는 충실하지만 **제도 논거와 선행기술이 비어 있다.**
아래 세 절이 그 칸을 채운다.

- **§2 제도적 공백** — 건설기술진흥법 시행규칙(2020) 300억 이상 공공공사 스마트 안전장비
  의무화 / 안전관리 수준평가 153개 세부지표는 2017년 틀 유지 / 발주청 평가는
  "적정 안전비용 지급 유무" 즉 **돈을 줬는지만 본다**.
  → *깔라고는 했고 예산은 집행됐는데, 그 장비가 현장을 실제로 덮는지 재는 지표가 없다.*
  BIGB가 "왜 배치 적정성을 평가해야 하는가"에 답할 때 필요한 논거가 이것이다.

- **§4 LH 정합성** — LH 스마트 안전기술 6대 항목 ①번(통합 안전관제시스템)에
  "출역관리·위치 관제" 명시 / 늘봄 A-Eye(2026-04-22 운영 개시)가 전국 LH 현장
  CCTV+IoT를 본사 통합관제로 집약 중 / 고도화 계획에 "인력·장비관리 기능 확대" 명시.

- **§6 선행기술 7건 + §9 출처 8건** — KIPRIS 결과가 아니라 문헌·특허 공개정보 기준.
  KT `KR102333803B1` 이 가장 가까운 특허이며 **제안서에 명시 인용이 필요**하다고 판단했다.
  카메라 tamper detection 과의 선긋기(카메라 안쪽 문제 vs 바깥쪽 문제)도 같은 절에 있다.

## 3. 미완 — 넘겨받는 쪽이 반드시 처리해야 할 것

### R1. KIPRIS 직접 검색 — **미수행**

가장 중요한 미완 항목이다. §6 대조표는 Google Patents·논문·언론 기준으로 만든 것이고
**KIPRIS 에서 직접 검색한 결과가 아니다.** 사전심사 실격 판정에 쓰이는 도구이므로
BIGB 주제(배치 적정성 평가)로 반드시 다시 돌려야 한다.

B안 기준으로 준비해 둔 검색식 5개 (BIGB 주제에 맞게 조정해서 쓸 것):

```
감시 공백 * 검지 이력 * 누적
이종 센서 * 미탐지 * 커버리지 진단
출입 기록 * 영상 검지 * 인원 대조
카메라 * 화각 * 사각지대 * 자동 도출
안전장비 * 이행 * 평가 지표 * 건설
```

BIGB 쪽으로는 최소 이 축들을 더 봐야 한다 —
`CCTV * 배치 * 최적화 * 건설현장` / `검출 성능 * 해상도 * 가림 * 커버리지` /
`카메라 배치 * 검출확률 * 평가`.

### R2~R5 (원문 §8 참조)

- **R2** 늘봄 A-Eye가 출역 데이터까지 수집하는지 **미확인**. 언론 보도는 "CCTV + IoT 센서"까지만.
  제안서에 현재형으로 쓰지 말 것 — "확장 방향"으로만 서술.
- **R3** 게이트 기록은 현장 전체 단위라 구역 단위 재실 인원은 동선 가정이 필요.
- **R4** 감시 공백이 시공사 평가에 쓰이면 반발 → **벌점이 아니라 개선 권고**로 포지셔닝.
- **R5** **개인정보 — 설계 제약이다.** 출역 기록 + 영상 결합은 개인 식별이 가능하므로
  개인 단위가 아니라 **시간대별 인원 수(카운트)만** 쓰도록 설계에 명시해야 한다.
  BIGB가 실데이터 확장을 언급할 경우 이 제약이 그대로 적용된다.

## 4. 검증 설계에 대한 메모

B안 §7의 논지는 BIGB에도 그대로 옮겨진다 —
*"실제 데이터가 아니지 않냐"* 에 대해 **"정답을 아는 환경에서 알고리즘 성능을 측정한 것"**
으로 답하는 구조다. BIGB는 가상 현장의 복셀·가림·화각을 전부 알고 있으므로 같은 방어가 선다.
다만 BIGB 쪽 실제 약점은 그게 아니라 **곡선이 SHWD 정지영상 합성 변형에서 나왔다는 점**이라,
합성 가림(수직 스트라이프)과 실제 비계 가림의 등가성은 별도로 한계에 적어두는 편이 안전하다.
