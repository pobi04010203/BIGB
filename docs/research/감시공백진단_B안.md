> 상태: 골격 확정, 선행조사 대부분 완료, KIPRIS 직접검색 미완

## 1. 한 문장 정의

**이종 안전장비의 검지 이력을 시공간 정합하여, 한 장비가 확인한 사실을 다른 장비가 놓친 지점을 누적함으로써 현장의 감시 공백을 지도화한다.**

핵심 발상: 울린 알림이 아니라 **울렸어야 하는데 울리지 않은 것**을 본다. (negative evidence)

## 3. 메커니즘 (데이터 전제 확보된 버전)

### 주 교차축 — 출역 기록 ↔ 영상 검지

- **건설근로자 전자카드제**: 2024.1.1부터 **공공 1억원 이상 전 현장 의무**. 전자카드 단말기 설치·운영 의무, 출·퇴근 태그 기록 생성. (3억 미만·지형 제약 현장은 공제회 앱 GPS 기록)
- 시간대별 게이트 태그 기록 → 현장 재실 인원 **N**
- 같은 시간대 AI CCTV가 검지·추적한 고유 인원 → **M**
- **N − M = 미관측 인원**. 이를 시간대·구역별로 누적하면 "사람이 있는데 보이지 않는" 구간이 드러남

### 보조 교차축

- 안전모 미착용 검지 발생률이 구역별로 극단적으로 낮음 → 검지가 안 되는 구역일 가능성
- IoT 계측기 이벤트 좌표에 대응하는 영상 이벤트 부재
- (확장) 접근감지 태그·스마트 밴드가 도입되면 그대로 축 추가 — 데이터 계약만 맞추면 됨

### 산출물

1. 현장 평면도 위 **감시 공백 히트맵**
2. 현장별 **커버리지 점수** (관측 가능 인시 / 총 재실 인시)
3. **개선 권고**: 카메라 N대를 어느 좌표로

## 4. LH 정합성 — 반려 사유 1에 대한 답

- LH는 시공하지 않고 **감독·평가**한다. 이 도구는 시공사 도구가 아니라 **발주처 도구**다
- **LH 스마트 안전기술 6대 항목 ①번(통합 안전관제시스템)에 "출역관리·위치 관제"가 이미 명시**되어 있음 → 이 제안이 쓰는 데이터가 LH가 이미 원하는 데이터다
- **늘봄 A-Eye**(2026.4.22 운영 개시)가 전국 LH 건설현장 CCTV+IoT 검지 데이터를 본사 통합관제로 모으고 있음 → 파이프라인이 이미 존재하고, 그 위에 얹는 진단 층
- 늘봄 A-Eye 고도화 계획에 **"인력·장비관리 기능 확대"** 명시 → 출역 데이터 결합이 LH 로드맵과 일치
- LH는 안전관리 수준평가의 **피평가자(발주청)이자 시공평가의 평가자** — 양쪽에 바로 쓰인다

## 6. 선행기술 대비 위치

| 대상 | 성격 | B안과의 관계 |
|---|---|---|
| CCTV Coverage Index (Choi & Lee, *Sensors* 2015) | 카메라 사양 + 3D 기하학으로 이론 계산·시뮬레이션 | **사전 설계 vs 사후 진단**. 실제 검지 이력을 쓰지 않음 |
| 배치 최적화 계열 (Art Gallery / Maximum Coverage) | 설치 전 최적 배치 | 동일 — 사전 설계 |
| KT KR102333803B1 (2021 등록) | 영상에서 인접 CCTV 관계 학습 → 화각 이탈 시 인계 | 운영 데이터를 쓰나 목적이 **추적 연속성**이지 공백 진단이 아님. 가장 가까운 선행기술, 제안서에 명시 인용 필요 |
| 카메라 tamper detection (상용 VMS 표준 기능) | 가림·초점흐림·방향전환 등 **카메라 자신의 영상 이상** 검출 | **카메라 안쪽 문제 vs 바깥쪽 문제**. 영상이 멀쩡한데 사건이 화각 밖에서 벌어진 경우는 tamper로 안 잡힘. 제안서에서 명시적 선긋기 필요 |
| 국토부 스마트건설 R&D III중점분야 「스마트 안전 통합 관제기술」 (2020~2025, 한국시설안전공단·중앙대·연세대) | 다양한 안전 데이터 통합·분석, 규칙-확률 기반 위험도 평가, 발주기관용 통합관제 | **위험을 얼마나 잘 찾는가(탐지 성능) vs 그 탐지 체계가 현장을 얼마나 덮는가(체계의 메타 평가)**. 대상이 근로자가 아니라 안전관리 체계 |
| KR101914228B1 / KR101721546B1 / KR20190065914A / KR101907964B1 | IoT 위치추적·영상 통합관제, RTLS 위험등급, 멀티모달 융합, 출입관리 통합 | 검지·경보 계열. 커버리지 진단 구성 없음 |

**검색 범위 안에서 "이종 장비 검지 이력의 교차 대조로 감시 공백을 역추정" 조합은 발견되지 않음.**

## 7. 검증 설계 — 원안 대비 개선점

원안(알림 융합·우선순위)의 최대 약점은 "시뮬레이션 알림에 정답이 없다"였다. B안은 다르다:

- 시뮬레이터가 **카메라 배치·화각·근로자 동선·실제 공백 위치를 알고 있음**
- 따라서 알고리즘이 그 공백을 얼마나 찾아냈는지 **재현율·정밀도로 정량 측정 가능**
- "실제 데이터가 아니지 않냐" → **"정답을 아는 환경에서 알고리즘 성능을 측정한 것"**으로 답할 수 있음

측정 지표(안): 공백 검출 재현율 / 오검출률 / 필요 관측 기간(며칠 치 이력이 쌓여야 공백이 유의하게 드러나는가)

## 8. 남은 리스크와 미완 과제

| # | 항목 | 상태 |
|---|---|---|
| R1 | **KIPRIS 직접 검색** | **미완**. 사전심사 실격 판정 도구이므로 반드시 수행 |
| R2 | 늘봄 A-Eye가 출역 데이터까지 실제로 수집하는지 | **미확인**. 언론 보도는 "CCTV + 계측기 등 IoT 센서"까지만. 고도화 계획에 인력관리가 있으나 현재형 아님 → 제안서에서 "확장 방향"으로 서술 |
| R3 | 구역 단위 재실 인원 추정 | 게이트 기록은 현장 전체 단위. 구역까지 쪼개려면 동선 가정 필요 → 1차는 현장 단위 공백률로 한정 |
| R4 | 시공사 수용성 | 감시 공백이 시공사 평가에 쓰이면 반발. **대응 논리: 벌점이 아니라 개선 권고로 설계** — "어디에 카메라를 더 두면 되는지"를 주는 도구로 포지셔닝 |
| R5 | 개인정보 | 출역 기록 + 영상 결합은 개인 식별 가능. **개인 단위가 아니라 시간대별 인원 수(카운트)만 사용**하도록 설계 명시 |

### KIPRIS 검색식 (직접 수행 필요)

- `감시 공백 * 검지 이력 * 누적`
- `이종 센서 * 미탐지 * 커버리지 진단`
- `출입 기록 * 영상 검지 * 인원 대조`
- `카메라 * 화각 * 사각지대 * 자동 도출`
- `안전장비 * 이행 * 평가 지표 * 건설`
